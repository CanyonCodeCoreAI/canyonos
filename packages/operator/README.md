# canyonos-operator

The Kubernetes operator that runs CanyonOS projects in a customer's cluster. A
project is a `CanyonProject` (its Redis, Global Controller and endpoint) and one
`CanyonAgent` per agent (a StatefulSet behind a headless Service). The operator
writes each ready replica's record and the routing table into the project's Redis,
in the same format the Docker and EC2 deploys write, so the Python runtime reads
both alike.

## Layout

- `api/v1alpha1/`: the CRD types (`canyonos.canyoncode.ai/v1alpha1`): CanyonProject,
  CanyonAgent and CanyonBuild. Core renders the first two in Python;
  `testdata/rendered.json`, generated by `packages/core/tests/kubernetes_contract.py
  rendered`, is what it renders for sample projects, and the tests here decode it with
  unknown fields refused.
- `cmd/`: the manager and its flags.
- `internal/controller/`: the reconcilers, and the dashboard's list of projects.
- `internal/builders/`: the Kubernetes objects each resource becomes, as pure functions.
- `internal/redisstate/`: the Redis records and routing table the operator writes.
  Their format comes from the Python side: `testdata/contract.json` is generated by
  `packages/core/tests/kubernetes_contract.py`, and the tests here check against it.
- `charts/canyonos-operator/`: the Helm chart. Its `crds/` and `files/` (the manager's
  RBAC role) are generated from the Go types and markers.

How it works: [Operator](../../docs/architecture/OPERATOR.md). How to use it:
[Kubernetes deployment](../../docs/guides/KUBERNETES.md).

## Development

Needs Go (see `go.mod`). Tools (controller-gen, envtest, golangci-lint) are
downloaded into `bin/` on first use.

```sh
make generate manifests   # deep-copy code, CRDs and RBAC after changing the types
make test                 # unit and envtest suites
make lint
```

CI (`.github/workflows/operator.yml`) runs the same and fails when generated files
were not committed. The whole path on a real cluster (`scripts/kind/up.sh`, then
`scripts/kind/e2e.sh`) is in
[Kubernetes on kind](../../docs/contributing/DEVELOPMENT.md#kubernetes-on-kind).
